# Kaisel 1.4.0 validation

Status: **unreleased**. The code changes are complete and unit-tested. Release gates that need real
devices are open. Do not tag 1.4.0 until every gate below is ticked.

## What 1.4.0 changes

| Area | Change | Why |
|---|---|---|
| Image classification | Explicit classes in `rasp_classify.c`: jailbreak injector (200, conclusive), instrumentation (205), trusted, marker (206), unknown external (201) | Broad markers (`crane`, `liberty`, `choicy`, ...) matched anywhere in a path were treated as conclusive injectors |
| Conclusive rule | Explicit allow-list of codes; 200 re-validated from its path. Replaces "not Frida means injector" | Same semantics in JB Check, Integrity Check, Keychain history and the server |
| Shared manifest | `Server/classification.json` feeds the C lists, the server and the parity tests | Stops the Swift, C and Python copies drifting |
| Remote rules | Image markers produce 206 only | Signed rules must not create a conclusive verdict |
| Server validation | Strict mode by default: supported SDK and schema, typed fields, server-side expected check set, no unknown codes, App Attest required | A report with incomplete checks or no attestation could be allowed |
| Server history | Keyed by App Attest-verified key only | A self-chosen Secure Enclave key is not device identity |

Full list: [CHANGELOG](../CHANGELOG.md). Defects, files and test output: [IMPLEMENTATION_REPORT.md](../IMPLEMENTATION_REPORT.md).

## Acceptance tests (spec P0.2)

`Server/tests/test_validation.py`. In strict mode none of these is `allow`: empty report, `checksCompleted`
0, `checksExpected` 0, a client-reduced expected set, missing check bits, unknown completion bits,
invalid bitmap types (string, float, bool, null, negative, over 32 bits, array), unsupported SDK or schema,
legacy 1.3.x report, unknown finding code, malformed signals, tampered payload, tampered App Attest
assertion, wrong or reused challenge, missing App Attest assertion, unbound Secure Enclave signature only.
Also tested: a valid complete report is `allow`; development exceptions (`--expected-distribution
development --debugger-expected`) allow an Xcode debug build; indicators alone give `step_up`; history is
written and read only for an App Attest-verified key; stale broad-marker history is ignored.
